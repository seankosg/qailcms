## B. 무엇을 만드는가

Plot D의 장비 항목(Sub System) 단위로 IFM 인계 준비 상태를 한 화면에서 보는 새 모듈이다. 항목마다 여섯 가지 선행 준비(T&C, OMM, 교육, 자산 태그, 준공도면, 서비스 리포트)가 **서로 독립적으로** 진행되고, 여섯 개가 다 닫히면 인수증(TOC) 신청 → IFM 검토 → 승인 → 인계 완료로 이어진다. 교육만 하위 절차가 있고, 해당 항목의 T&C가 끝난 뒤에만 시작할 수 있다.

## C. 단계 (한 단계씩 승인 후 진행)

**0단계 — 모듈 등록**
`rcl_module_config` 에 TOC 1행(소유자 칸 pic·eng, 팀 칸 team), 백업 대상 표 등재, 화면·임포트·롤백·지문 등 등록 지점 전부에 TOC 추가. 검산: 등록 지점 목록에서 누락 0. 실제 사용자 1명으로 쓰기 가능 여부 확인(pic·eng 이 비어 있어 팀 범위만으로 편집이 되는지).

**1단계 — 표와 규칙**
아이템·단계 카탈로그·단계 진행·교육 세션·항목↔세션 링크·세션 코멘트·변경 이력·임포트 로그·설정 표 생성. 카탈로그에 밴드 7개와 완료 코드 사전 시드. 변경 이력 트리거, 검출 뷰, T&C→교육 가드(시딩 스위치 포함). 검산: 밴드 7개, 코드형 단계마다 완료 코드 사전이 비어 있지 않음.

**2단계 — 조회·판정 함수**
`toc_eval_as_of` / `toc_rows_as_of`. 기준일 이후 실적 마스킹, 밴드별 독립 상태, 코드→완료 판정 정규화, 교육 세션 롤업(함수 내부 계산), 판정 8종, 준비도(분모에서 N/A 제외), 최대 지연 단계 보고. 검산: 판정 분포 합 = 활성 항목 수, 밴드 매트릭스 셀 합 = 항목 수 × 7, 기준일을 과거로 돌리면 실적이 전부 사라지는지.

**3단계 — Raw Data 화면**(영어 UI)
항목 × 밴드 피벗 표, 인라인 편집, 벌크 편집, 기준일 선택, 컬럼 설정. 판정·집계는 조회 함수 결과만 사용.

**4단계 — 시딩 (원천 파일 수령 후)**
SOW Matrix 104 + 외부 항목 11 = 115행, 교육 세션, 항목↔세션 매핑 적재. 검산: 항목 수 = 원천 행 수, 세션 수 = 원천 세션 수, 원천의 승인 건수 = 인계 완료 건수, 평가서 수령 세션 수 일치, 외부 항목 11건이 TOC Ready 로 잘못 뜨지 않는지.

**5단계 — 왕복 Export/Import + 로그·롤백**
내보낸 양식을 그대로 다시 넣으면 변경 0건. IFM 소유 값은 HDEC 양식으로 넣으면 거부. T&C 미완 항목에 교육 실적 입력 시 거부.

**6단계 — Progress · Dashboard · Detail**
밴드 7개를 나란히 놓는 진행 화면, 시스템별 준비도 매트릭스와 상태 카드, 항목 상세(밴드 체크리스트·연결 세션·피드백 왕복·협의 패널).

## D. 하지 않는 것

기존 SPL 표·함수·뷰·권한 격자·마이그레이션 수정, 판정의 화면 재계산, 밴드 간 순서 가정(교육 게이트 제외), IFM 상태를 완료 판정에 사용, 코드값 하드코딩, PIC·ENG 임의 입력, BMS 항목·타 모듈 연동·문서 표·재제출 라운드.

## E. 지금 필요한 것

원천 파일 3종(SOW Matrix, Training Status, 매핑 파일). 없어도 0~3단계는 진행 가능하며, 4단계부터 파일이 필요하다.
