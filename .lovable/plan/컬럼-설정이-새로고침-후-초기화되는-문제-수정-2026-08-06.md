# 컬럼 설정이 새로고침 후 초기화되는 문제 수정

## 확인된 사실

- 서버에는 설정이 정상 저장되어 있습니다. TM Raw Data 기준 최근 저장 행의 `order` 37개(전체 38개 컬럼 - 고정 `task_no`), `frozenExtras` 5개, `visibility` 9개가 그대로 들어 있습니다.
- 즉 "저장이 안 되는" 문제가 아니라 **불러오기가 실패했을 때 기본값으로 되돌아가고, 그 기본값이 곧바로 서버에 덮어쓰기 되는** 구조 결함입니다.

## 원인 (`src/hooks/useUserViewPreference.ts`)

1. `ready` 판정이 실패를 구분하지 않습니다. 설정 조회가 오류로 끝나면 `isPending`이 false가 되어 `ready = true`, `state = null` 이 되고, 각 화면은 이를 "저장된 설정 없음"으로 해석해 **기본 컬럼 배치를 적용**합니다.
2. 기본 배치가 적용된 직후 저장 effect가 돌면서 그 기본값을 서버에 upsert → **정상 저장돼 있던 설정이 파괴**됩니다.
3. 로컬 캐시 폴백이 동작하지 않습니다. `initialState` 를 첫 렌더에서 한 번만 읽는데, 그 시점에는 로그인 사용자 id가 아직 없어 항상 `null` 입니다.
4. 훅이 매 렌더 새 객체를 반환하고, `save()` 안에서 `setQueryData` 로 캐시를 갱신해 다시 렌더를 유발합니다. TM 페이지의 저장 effect 의존성에 `viewPref` 객체가 들어 있어 **렌더마다 저장이 재실행**되고, 위 2번의 덮어쓰기가 즉시 확정됩니다.

## 수정 내용

훅 한 곳을 고치면 TM / SM(Defect) / ABD / DMR / MWS 5개 화면에 동일하게 적용됩니다.

`src/hooks/useUserViewPreference.ts`
- 조회 실패 시 `ready`를 false로 유지하고 `error` 상태를 함께 반환합니다. 불러오지 못한 상태에서는 화면이 기본값 복원을 시작하지 않습니다.
- 조회 실패 시에도 로컬 캐시가 있으면 그 값을 사용하도록 폴백을 살립니다. `initialState` 를 첫 렌더 고정값이 아니라 **사용자 id가 확정된 뒤 읽는 값**으로 바꿉니다.
- "성공적으로 불러오기 완료" 플래그를 두고, 그 전에는 `save()` 가 서버 upsert를 하지 않도록 차단합니다(로컬 캐시 기록은 유지).
- 반환 객체와 `save` 콜백을 메모이제이션해 렌더마다 저장이 재실행되지 않게 합니다.
- 조회 재시도를 1~2회 허용해 일시적 네트워크/토큰 지연으로 인한 실패를 흡수합니다.

`src/components/task-management/raw-data/TaskManagementRawDataPage.tsx`
- 저장 effect 의존성에서 `viewPref` 객체를 빼고 `viewPref.save` 만 사용하도록 정리합니다(무한 저장 루프 제거).

ABD / SM / DMR / MWS 화면은 이미 `ready` 게이트를 쓰고 있어 훅 수정만으로 동일하게 보호됩니다. 별도 UI 변경은 없습니다.

## 검증

- TM Raw Data에서 컬럼 순서·표시·고정을 바꾸고 새로고침해 그대로 유지되는지 확인합니다.
- 저장 요청이 렌더마다 반복되지 않고 변경 시 1회만 발생하는지 확인합니다.
- 저장 행의 `updated_at` 이 조작하지 않은 새로고침만으로는 갱신되지 않는지(= 불필요한 덮어쓰기 없음) DB로 실측합니다.
