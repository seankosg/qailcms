## B. TOC 표 컬럼 구성

고정 후보(핀 기본 1개: 항목번호) → 항목번호 · 장비명 · 상위 시스템 · 위치 · 담당 트레이드 · 공급사 · 준비 밴드 7열(T&C · O&M · 교육 · 자산태그 · 준공도면 · 서비스리포트 · 인수증) · 준비도(%) · 인수증 번호 · 인수증 상태 · 인계 예정일 · 판정 · 최대 지연 단계 · 담당자 2열 · 관측일.

밴드 7열은 SM의 Progress 가상 컬럼(`:703–714`)과 같은 방식의 파생 열로 만들고, 마우스를 올리면 그 밴드에 속한 단계별 상태·계획·실적을 그대로 보여 줍니다. 판정·준비도·밴드 상태는 전부 정본 조회 결과만 사용하고 화면에서 다시 계산하지 않습니다.

## C. 사전 보고 — 승인이 필요한 차이 5건

**C-1. 필터·정렬·페이지 계산 위치.** SM은 서버 검색·패싯 함수(`defect_items_search` / `_facets`)를 씁니다. TOC는 정본이 전체를 한 번에 돌려주는 방식(115건)이라 같은 함수가 없습니다. 화면 동작·모양은 SM과 동일하게 두고, 필터·정렬·패싯 건수·페이지 나누기만 받아온 결과 안에서 계산합니다. TOC 전용 검색 함수를 새로 만들지는 않습니다.

**C-2. 컬럼 라벨 변경 기능 제외.** SM의 라벨 변경은 SM 전용 필드 설정 표에 저장됩니다. TOC에는 그 표가 없어 관리자 라벨 편집만 빼고, 순서·노출·핀·너비는 계정별로 저장·복원합니다.

**C-3. 탭 구성.** SM은 Unclosed / Closed입니다. TOC는 **In Progress(인계 완료 아님) / Handed Over(인계 완료) / All** 3탭으로 두는 것을 제안합니다(현재 1 / 114 / 115).

**C-4. 행 선택·일괄 수정·Critical 열·AI 분류·전체 XLSX 제외.** TOC는 쓰기 경로(수정 저장 함수·권한 검증)가 아직 없습니다. 이번 이식은 조회 UI까지이고, 선택·일괄 수정은 임포트 단계와 함께 다음 라운드로 둡니다.

**C-5. 행 클릭 상세 이동 보류.** TOC 상세 화면이 없어 클릭은 아무 동작도 하지 않습니다(상세 화면 구축 시 연결).

## D. 검산 (구현 직후 보고)

- 표 행수 = 정본 총건수(필터 없음 상태에서 115), 탭 3개 건수 합 = 115
- 판정 카드 합계 = 현재 필터 결과 행수(불일치 시 화면에 MISMATCH 표기 유지)
- 밴드 열 상태 분포 = 정본 밴드 집계와 동일(각 115)
- 스티키 컬럼 배경 불투명 확인(스크롤 중 뒤 열 비침 없음)
- 기준일을 과거로 옮기면 실적 열이 비는지

## E. 하지 않는 것

SM 원본 파일 수정, 판정·준비도의 화면 재계산, TOC 전용 검색 RPC 신설, 컬럼 라벨 서버 저장, 쓰기(인라인·일괄) 기능.
