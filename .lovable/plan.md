# SM Raw Data 검색 — 쉼표 다중 번호 OR 검색 + 검색 버튼

## 목표
SM Raw Data 상단 검색창에 `100008, 100010, 182992, 1012823, 199832` 처럼 여러 값을 입력하고 검색 버튼을 누르면, 그 값들 중 **하나라도 해당하는 항목 전부**가 리스트업된다.

현재는 쉼표 토큰이 **AND** 로 결합되어(모든 토큰을 동시에 만족해야 함) 서로 다른 번호를 나열하면 결과가 0건이 된다. 이를 **OR** 로 바꾼다.

참고: 예시 번호 5개 중 실제 데이터에 존재하는 것은 `100008`, `100010` 두 건이며 `182992`, `1012823`, `199832` 는 현재 DB 어느 테이블에도 없다. 규칙 수정 후에도 존재하는 항목만 나오므로 예시에서는 2건이 표시된다.

## 동작 규칙 (확정)
- 쉼표(,) 로 구분한 각 토큰은 **부분일치(ILIKE)** 로 검색하고, 토큰끼리는 **OR** 로 결합한다.
- 숫자만으로 된 토큰은 기존과 동일하게 **번호 컬럼(Issue No)** 범위로 검색한다(숫자가 다른 텍스트 컬럼에 우연히 섞여 잡히는 잡음 방지).
- 검색어 전체와 컬럼 필터(헤더 필터)·탭·상태 조건은 기존대로 **AND** 로 결합된다.
- 입력 즉시 자동 검색(300ms 디바운스)은 제거하고, **검색 버튼 클릭 또는 Enter 키**로만 실행한다. 입력창을 비우고 검색하면 전체로 복귀(초기화 버튼도 함께 제공).

## 화면 변경
`src/components/defect-management/raw-data/DefectRawDataPage.tsx`
- 검색창 우측에 `검색` 버튼 추가, Enter 키 제출 지원, 디바운스 useEffect 제거(URL `q` 반영은 버튼/Enter 시점에 수행).
- placeholder 문구를 `Search defects... (comma = OR)` 로 변경.
- 입력값이 URL 의 적용된 검색어와 다를 때 버튼을 강조하여 "미적용 상태"를 표시.

## 서버 변경 (마이그레이션 1건)
동일한 토큰 처리 블록이 3개 함수에 중복되어 있으므로 셋 다 같은 마이그레이션에서 수정한다.
- `public.defect_items_search`
- `public.defect_items_search_ids`
- `public.defect_items_facets`

각 함수의 `_q` 처리 루프를 아래로 교체:
- 토큰별 조건식을 만들고 `or` 로 누적한 뒤, 마지막에 `_where_sql := _where_sql || format(' and (%s)', _q_sql)` 로 한 번만 AND 결합.
- 숫자 토큰: `(source_issue_no ilike '%tok%' or subcontractor_issue_no ilike '%tok%' or issue_no::text ilike '%tok%')`
- 그 외 토큰: 기존 `_search_cols` 전체에 대한 ILIKE OR 묶음.

시그니처는 변경하지 않으므로 `DROP FUNCTION` 은 불필요하다(오버로드 발생 없음). UI 불변 원칙 범위 밖의 요청된 UI 변경(검색 버튼)만 수행한다.

## 검증
- `defect_items_search(_q => '100008, 100010, 182992')` 가 2행을 반환하고 `total_count` 도 2인지 실측.
- 단일 토큰 검색 결과가 기존과 동일한지(회귀 없음) 실측.
- 검색어 + 헤더 컬럼 필터 동시 적용 시 AND 로 좁혀지는지 확인.
- Facets(헤더 필터 후보 목록)와 전체선택용 `_search_ids` 건수가 목록 건수와 일치하는지 대조.
