## 3. Import 파이프라인 (SHAW Defect Import 완전 준용)

SHAW Defect Import 모듈의 위저드/훅/컨텍스트/RPC 구조를 QAIL Spare Part 스키마에 맞춰 그대로 이식합니다. (SHAW 소스 구조 실조사 결과는 빌드 진입 시 각 파일 1:1 매핑; 아래는 사용자가 명시적으로 요구한 "완전 동일" 요건을 반영한 확정 구조입니다.)

### 3.1 라우트 & 페이지

- `/closure/spare-part/import` (`SparePartImportPage.tsx`) — **다단계 위저드 (Stepper)**
- `/closure/spare-part/import/logs` (`SparePartImportLogsPage.tsx`) — 임포트 이력 목록/상세
- 관리자만 접근(`RoleGuard`)

### 3.2 위저드 스텝 (SHAW Defect Import와 동일 순서·명칭)

1. **Upload** — Dropzone. `.xlsx/.xls/.xlsm` 허용. 파일 해시(sha256) 계산 후 최근 24h 내 동일 해시 이미 임포트되면 경고
2. **Sheet & Header** — 시트 선택(default `Raw Data`) + 헤더 행 자동 탐색(첫 30행 스캔, `doc_ref/plot` 또는 SHAW의 시그니처 컬럼 발견 시 확정). 사용자가 수동 조정 가능
3. **Header Mapping** — 감지된 소스 헤더 목록을 좌측, 46개 표준 필드 + "Custom field 만들기" 옵션을 우측 드롭다운으로. `spare_part_header_mappings`에서 이전 매핑 자동 로드, 사용자가 저장하면 다음 임포트에 자동 적용. 표준 필드에 매핑 안 되면 커스텀 필드 등록 유도
4. **Custom Fields** — 스텝 3에서 커스텀으로 지정된 헤더들을 검토. `data_type`(text/number/date/boolean), `display_name`, `sort_order`, `is_enabled` 설정 후 `spare_part_custom_fields`에 upsert. 이후 Raw Data 페이지에서 동적 컬럼으로 노출됨
5. **Preview & Validate** — 파싱 결과 프리뷰 테이블(첫 50행). §7 검증(총 98/49×2, plot prefix 일치, 진행률 0–1, 날짜 유효성, boolean 정합) 결과 상단 배지. Warnings/Errors 아코디언 목록. 에러 있으면 Confirm 비활성
6. **Confirm & Run** — "Confirm Import" 클릭 → RPC 실행 → 진행 프로그레스 → 결과 요약(inserted/updated/skipped) + 검증 리포트 + "Go to Raw Data" / "View Log" 액션

Stepper는 좌우 [Back]/[Next] + 상단 스텝 인디케이터, 각 스텝 상태(완료/진행/미완) 표시. 뒤로 가도 이전 단계 상태 유지(SHAW 동형).

### 3.3 상태 관리 — `ImportContext`

SHAW `ImportContext.tsx` 그대로 이식:

- 현재 스텝, 파일 파일 메타(name/size/hash), workbook 객체, 선택된 sheet/headerRow, 파싱된 rows[], 헤더 매핑, 커스텀 필드 목록, 검증 결과, 실행 결과
- Provider는 `/closure/spare-part/import` 라우트 서브트리 감쌈
- 페이지 이동/새로고침 시 `sessionStorage`에 부분 복원(파일 자체는 재선택 요구)

### 3.5 서버 RPC

- `spare_parts_import_run(payload jsonb)` — SECURITY DEFINER + admin 체크. payload = `{rows, header_map, custom_fields, file_meta}`. 트랜잭션 내:
  1. 필요한 신규 `custom_fields`가 있으면 upsert
  2. `spare_parts_raw`에 upsert `ON CONFLICT (doc_ref) DO UPDATE`, 표준 필드는 mapped 값, 나머지 원본 헤더는 `raw_payload`로, 매핑된 커스텀 헤더 값은 `custom_payload`로
  3. `spare_parts_import_logs`에 실행 결과 기록
  4. 반환: `{log_id, inserted, updated, skipped, warnings, validation}`
- 삭제 없음(idempotent). 이번 파일에 없는 기존 doc_ref는 warnings에 기록

### 3.6 Import Logs 페이지

- 목록: 실행일시/실행자/파일명/inserted/updated/skipped/warnings 수/검증 통과 여부
- 상세 다이얼로그: header_map JSON, unknown_headers, 전체 warnings 목록, 검증 세부(§7 항목별 pass/fail), 재검증 버튼(참조용)
- 페이지네이션, 검색(파일명), 날짜 범위 필터 (SHAW `ImportLogsPage.tsx` 준용)

## 11. Aconex 승인 상태 Sync 모듈 (신규)

Aconex Export xlsx를 업로드해 `spare_parts_raw`의 `approval_code`, `approval_status`, `revision` **3개 컬럼만** 갱신하는 재실행 가능 sync. 그 외 컬럼(category, quantities, procurement 등)은 절대 건드리지 않음.

### 11.1 라우트 & UI 흐름 (`/closure/spare-part/aconex-sync`)

Import 위저드와 별개의 3-스텝 흐름 (SHAW Defect Import 위저드 UX를 축약 채용):

1. **Upload** — 하나 이상 파일 드롭. 각 파일에서 `Docs` 시트 자동 탐색, 헤더 행은 상단 30행 내에서 `Document No`+`Status` 포함 셀 위치로 동적 확정
2. **Preview & Map** — 파싱 결과 + 미매핑 Status 값 목록. 사용자가 `spare_part_status_mapping`에 매핑 추가/편집. Change Preview 테이블(§11.4) 표시
3. **Apply** — RPC 실행, 결과 요약, `spare_parts_sync_log`에 기록

### 11.2 Status 매핑 (`spare_part_status_mapping`)

시드:

| source_status_raw | approval_code | approval_status |
|---|---|---|
| `A - Approved` | `A` | `APPROVED` |
| `B - Approved with Comments` | `B` | `APPROVED WITH COMMENTS` |
| `C - Revise and Resubmit` | `C` | `REVISE AND RESUBMIT` |
| `D - Rejected` | `D` | `REJECTED` |
| `For Review` | `UR` | `UNDER REVIEW` |

- 매핑에 없는 Status는 **자동 유추 금지**, 리뷰 리스트에 넣어 사용자 결정 대기
- Revision 정규화: `001` → `REV 1`, `002` → `REV 2`, `010` → `REV 10` (`revision-normalize.ts`)

### 11.3 매칭 & 업데이트 규칙 (프롬프트 §4 그대로)

1. `Document No` == `doc_ref` (trim, case-sensitive) 정확 일치만
2. 새 값 vs 기존 값이 하나라도 다를 때만 UPDATE, old→new 기록
3. **`is_duplicate=true` (DP) 행**은 자동 갱신 금지. 별도 목록에 두고 사용자가 각 행마다 "Apply / Skip" 선택
4. Export에 있으나 DB에 없는 `Document No`는 skip + 리포트(신규 insert 안 함)
5. DB에 있으나 Export에 없는 행은 유지 + 리포트("not covered by this export"), plot별 그룹핑
6. 같은 export 내 동일 `Document No` 중복은 최고 `Revision` 채택 + 리포트
7. `doc_ref` prefix로 plot 파생 후 DB `plot` 컬럼과 불일치 시 즉시 중단

### 11.4 Change Preview 테이블 (프롬프트 §6)

| doc_ref | subject | 항목 | 기존 값 | 새 값 |
|---|---|---|---|---|
| 9207-…-00002 | Hearing Assistive … | approval_code | C | A |
| 9207-…-00002 | Hearing Assistive … | approval_status | REVISE AND RESUBMIT | APPROVED |
| 9207-…-00002 | Hearing Assistive … | revision | REV 1 | REV 2 |

- 필터: 변경된 항목만 / DP-held만 / unmatched만
- 요약 카드: matched / changed / unchanged / DP-held / unmatched-export / db-uncovered
- "Apply Changes" 버튼은 미매핑 Status 0 && 사용자 DP 결정 완료 시 활성

### 11.5 서버 RPC `spare_parts_aconex_apply(payload jsonb)`

- SECURITY DEFINER + admin 체크
- payload: `{changes: [{doc_ref, approval_code?, approval_status?, revision?}], file_meta, generated_on, dp_decisions}`
- 트랜잭션: UPDATE만 실행 (INSERT/DELETE 없음), `updated_by/updated_at` 기록, `spare_parts_sync_log` 기록
- 반환 요약 카운트

### 11.6 §7 검증 (Aconex 프롬프트)

- 갱신된 모든 row `approval_code ∈ {A,B,C,D,UR,DP}`, `approval_status` 매핑표 정합
- `spare_parts_raw` 행 수 불변 (INSERT/DELETE 없음)
- prefix↔plot 정합 유지
- Preview에서 표시한 changed count == 실제 UPDATE count
- **동일 파일 재실행 시 changed = 0** (idempotency)
