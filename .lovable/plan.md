# SM 매트릭스 Date 열 · 드릴다운 정합 교정

## 실측 확인 결과 (Plot D · Tower · TENANT · ARCH · Rect, as-of 2026-09-19)

| 항목 | 화면 표시 | 실측 정답 |
| --- | --- | --- |
| Level 66 Date (잔여 4건) | 10/Mar (2027-03-10) | 2026-10-23 (잔여 4건의 최대 계획일) |
| Column Total Date (잔여 42건) | 10/Mar (2027-03-10) | 2027-02-21 (잔여 42건의 최대 계획일) |
| Level 66 드릴다운 | A.Rectified ≤ 2026-09-19 → 종결 7건 | 잔여 4건이 나와야 함 |

원인 2가지를 확정했습니다.

1. **Date 값 모집단이 틀렸습니다.** 날짜 집계 RPC(`defect_snag_stage_dates_json`)가 셀 안의 **모든 항목**에서 계획일 최댓값을 뽑습니다. 이미 완료된 항목(예: 61709·62028·62029, 계획 2027-03-10·실적 2026-08-29 완료)의 먼 계획일이 섞여, 잔여 항목에는 없는 날짜가 표시됩니다. Column Total도 같은 이유로 잘못된 날짜를 보여줍니다(“가장 늦은 날짜”는 맞게 뽑고 있으나, 대상 집합이 잔여가 아니라 전체).
2. **드릴다운 조건이 셀과 반대입니다.** 잔여·Date 셀을 눌러도 `실적일 ≤ as-of`(=완료 항목) 필터로 이동합니다. 그래서 잔여 4건 대신 완료 7건이 보입니다.

## 고칠 내용

### 1) Date 집계를 잔여/완료로 분리 (DB)
`defect_snag_stage_dates_json`을 스테이지별로 두 갈래 최댓값으로 재작성합니다.
- 잔여(= 해당 스테이지 실적일이 없거나 as-of 이후)만 모아 **계획일 최댓값** → 미완료 셀에 표시
- 완료(= 실적일 ≤ as-of)만 모아 **실적일 최댓값** → 잔여 0 셀에 표시
- 판정은 기존 정본 `_snag_done_asof`와 동일한 식을 사용하고, 셀·행·빌딩·열·블록 소계는 현행 조립 유틸(`stage-dates.ts`)에서 그대로 MAX로 접습니다. 구 시그니처는 같은 마이그레이션에서 DROP.

이로써 Column Total 날짜도 “그 컬럼 잔여 항목 중 가장 늦은 계획일”로 자동 정합됩니다.

### 2) 잔여 셀 드릴다운을 잔여 조건으로 (DB + 화면)
- `defect_items_search` / `defect_items_search_ids` / counts에 `stage_remaining` 연산자 추가: 스테이지 + as-of를 받아 `_snag_done_asof`가 false인 행만 남김(정본 재사용, 규칙 재구현 없음).
- 매트릭스 드릴다운(`DeSnagMatrixBlock.goCell`)은 모드에 따라 분기:
  - 잔여 계열 모드(잔여 개수·잔여 %·잔여+Date, Each Date) → `잔여(stage, as-of)` 조건
  - 개수·% 모드 → 현행 `실적일 ≤ as-of` 유지
  - Issued 열은 현행 유지
- Raw Data 화면에 잔여 조건 칩(`Remaining — <stage> @ <as-of>`)을 붙여 어떤 조건으로 들어왔는지 보이게 합니다(기존 URL 파라미터 `remaining_stage`·`remaining_asof` 사용).

### 3) 무작위 재검증
2026년을 넘어가는 날짜 셀 중 무작위 8개(스테이지·팀·블록 섞어서)를 골라 화면 표시값 ↔ SQL 실측값 ↔ 드릴다운 행수를 대조한 표를 보고합니다. Column Total 날짜도 컬럼별로 같은 방식으로 검산합니다.

## 바뀌지 않는 것
매트릭스 열 구성·토글·색상·문구·엑셀 형식은 그대로입니다. 잔여 개수·%·Ready/Overdue 음영 규칙도 변경 없습니다. 엑셀 다운로드는 화면과 같은 날짜를 쓰므로 자동으로 함께 교정됩니다.
